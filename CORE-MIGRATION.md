# Coordinated final modern-core migration

The active candidate changes only the canonical modern product. It moves from
phase 1 head `350437ed5e26df6a7c4ec58105d5993c224edf3d` and core
`7a8a321d04323d49319d0b08e6093a0ddce36b27` to the exact shared core commit
`a794e3b4a8813b012f2c4faa3da82b78d4a90214`.

The central owner reported reviewed-source CPU qualification and a bounded
synthetic CUDA fixture for that exact core. This product runs CPU fixtures only.
Those shared fixtures do not qualify native Z-Image training, model precision,
resources, image quality, audio, wide vectors or packed Flux responses.

## Identity and compatibility

The distribution is now version 0.1.3 with cohort
`embedded-zimage-adapter-gan-pg094-hg-hndl010-v4`. The namespace, entry points,
initialization policy and native response/row protocol version 2 are unchanged.
The dependency is pinned in pyproject.toml. A single regenerated recursive lock
binds all 50 installed core source/data files, including LICENSE, while excluding
only generated bytecode. Every installed file was compared with the exact Git
source tree, and direct_url.json identifies the exact a794 commit.

Old version 0.1.2/cohort v3 packets retain their original core and source pin.
The new candidate refuses actual old training, raw and EMA packets before native
preparation; their file hashes remain unchanged. No compatibility or migration is
silently assumed. Caches binding the old core identity must be regenerated for the
new cohort. The historical/default trainer, umbrella source, archival evidence
and model license are untouched.

## Bounded product integration fixes

The new core's cleanup helper takes an explicit primary exception and its sessions
keep failed closes retryable. Product factory and observation wrappers now pass
that primary exception explicitly. Hook cleanup attempts every removal and retains
failed handles for a subsequent close attempt. No GAN equation, teacher/neutral
response, native guidance 0 mapping to shared guidance 1, bank architecture,
projection computation or HNDL graph operation was changed.

The numerical reference is deliberately bounded. The shared LoRAModule AST was
verified equal to the historical module at the archived source commit. Shared
LoRANetwork discovery differs from the historical network. The tests cover native
outputs, VJPs and the tiny model's shared target names; they do not establish full
historical discovery parity.

## Reproducible qualification

Build from the repository root with `python -m build --no-isolation .`. Install
the wheel and sdist into an isolated CPU environment using the exact public Git
dependency. Run tests outside the checkout with:

```sh
python -m pytest -c /dev/null --import-mode=importlib -q /path/to/repository/tests
python -m pip check
```

Current receipts are recorded in qualification.json. The suite covers both
released presets, OFF/raw/EMA responses, exact split resume, native-only inference
after data removal, source-lock tamper, old identity refusal, cleanup errors,
retryable close, rollback, caller RNG and borrowed native state.

Deep same-config training-signature checks still follow reversible preparation.
No universal pre-hook refusal, native GPU admission or unsupported behavior is
claimed. Claude RETURN review and root-controlled merge decisions remain pending.
No workflow, visibility, access, release or deployment changes are made.
